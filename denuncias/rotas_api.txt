------- Rotas -------
    GET    /denuncias/
    POST   /denuncias/
    GET    /denuncias/{id}/
    PUT    /denuncias/{id}/
    PATCH  /denuncias/{id}/
    DELETE /denuncias/{id}/
---------------------

---------- Autenticação e Permissões ----------
Todas as rotas de /denuncias/ exigem usuário autenticado (permissions.IsAuthenticated),
e agora também passam pela permissão customizada DenunciasPermission.

Headers obrigatórios:
- Authorization: Bearer TOKEN_DE_ACESSO

Content-Type (ATENÇÃO: mudou por causa do envio de fotos):
- POST /denuncias/            -> multipart/form-data (campos de formulário + arquivos no campo "fotos")
- PUT / PATCH /denuncias/{id}/ -> application/json quando NÃO há foto nova
                                  multipart/form-data quando for ENVIAR foto nova
- GET e DELETE                -> sem corpo, então não precisam de Content-Type
- Em multipart NÃO defina o Content-Type manualmente: deixe o fetch/axios/cliente HTTP
  gerar sozinho, pois ele inclui o "boundary" que separa os campos. Se for escrito à mão,
  o envio falha.

Regras da DenunciasPermission (checadas por objeto, não pra lista):
- GET /denuncias/{id}/ (detalhar)  -> só ONG, o dono (usuario da denúncia) ou admin
- PUT / PATCH /denuncias/{id}/     -> só ONG, o dono (usuario da denúncia) ou admin
- DELETE /denuncias/{id}/          -> só admin (is_superuser)
- POST /denuncias/                 -> qualquer usuário autenticado pode criar

Obs importante: GET /denuncias/ (listagem) NÃO é filtrado por essas regras —
permissão de objeto só é checada em rotas de detalhe/edição/remoção (com {id}).
Ou seja, a listagem continua retornando todas as denúncias pra qualquer
usuário autenticado, mesmo que ele não seja dono/ONG/admin de cada uma.
-----------------------------------

---------- Listar (GET /denuncias/) ----------
Retorna uma lista com todas as denúncias cadastradas.

Suporta filtros via query params (DjangoFilterBackend):
- ?cidade=Apodi
- ?usuario_id=1
- ?status=aberto

Exemplo: GET /denuncias/?cidade=Apodi&status=aberto

a API vai devolver uma lista de objetos, no formato:
[
  {
    "id": 1,
    "titulo_caixinha": "Cachorro ferido na praça",
    "tipo_animal": "Cachorro",
    "quantidade": 1,
    "latitude": "-5.660800",
    "longitude": "-37.796900",
    "cidade": "Apodi",
    "condicao": ["Machucado", "Sangrando"],
    "descricao": "Animal encontrado ferido próximo à praça central",
    "motivo": "Maus tratos",
    "data_encontro": "2026-08-05T14:30:00Z",
    "data_status_aceito": "2026-08-05T15:00:00Z",
    "status": "aberto",
    "ong": null,
    "criado_em": "2026-08-05T14:35:00Z",
    "usuario": 3,
    "fotos": [
      {
        "id": 10,
        "url": "https://xxxx.supabase.co/storage/v1/object/public/pet-photos/denuncias/3/a1b2c3.webp",
        "ordem": 1
      },
      {
        "id": 11,
        "url": "https://xxxx.supabase.co/storage/v1/object/public/pet-photos/denuncias/3/d4e5f6.webp",
        "ordem": 2
      }
    ]
  }
]

"fotos" é sempre uma LISTA (de 1 a 4 itens), já ordenada. A foto de ordem 1 é a capa:
para mostrar a miniatura no card, use fotos[0].url. Cada "url" abre direto num <Image>.
Os campos de relação chegam como "ong" e "usuario" (ids), e não "ong_id"/"usuario_id".

---------- Criar (POST /denuncias/) ----------
Formato: multipart/form-data (NÃO é mais JSON). As fotos vão junto, no campo "fotos".
A API redimensiona cada foto, converte pra WebP, envia pro Supabase Storage e cria sozinha
a lista "fotos" da denúncia, com as URLs públicas.

Campos do formulário (obrigatórios):
  titulo_caixinha  = Cachorro ferido na praça
  tipo_animal      = Cachorro
  quantidade       = 1
  latitude         = -5.6608
  longitude        = -37.7969
  cidade           = Apodi
  condicao         = Machucado          <- repetir o campo, 1 vez por item da lista
  condicao         = Sangrando
  descricao        = Animal encontrado ferido próximo à praça central
  motivo           = Maus tratos
  status           = aberto             <- obrigatório na validação, mas a API ignora o
                                           valor e sempre grava "aberto"
  fotos            = (arquivo de imagem)  <- OBRIGATÓRIO: de 1 a 4 arquivos
  fotos            = (arquivo de imagem)  <- repetir o MESMO campo "fotos" 1 vez por imagem

COMO ENVIAR VÁRIAS FOTOS (importante):
- Use sempre o mesmo nome de campo: "fotos". NÃO use "foto1", "foto2", "fotos[]" nem "fotos[0]".
- Cada imagem é uma parte separada do formulário com o nome "fotos" (igual ao "condicao").
- A ordem de envio vira a "ordem" na resposta: a 1ª foto enviada é a capa.
- Mesmo com uma foto só, o campo continua se chamando "fotos".
- Não mande as imagens em base64 nem dentro de JSON: precisam ir como ARQUIVO no multipart.

Regras das fotos:
- Mínimo de 1 e máximo de 4 fotos por denúncia. Sem nenhuma, a API devolve 400.
- Formatos aceitos: JPEG, PNG e WebP. Fotos HEIC/HEIF (padrão do iPhone) NÃO são aceitas:
  converter pra JPEG no app antes de enviar (ex.: expo-image-picker/ImageManipulator).
- Tamanho máximo: 10 MB por foto. Dica: reduzir no app antes (ex.: lado maior ~1600px,
  qualidade 0.8) economiza dados móveis e deixa o envio mais rápido.
- A API reduz cada foto pra no máximo 1600px e converte pra WebP; os metadados
  (GPS/EXIF) são removidos.
- Se UMA das fotos for inválida, a denúncia inteira NÃO é criada (tudo ou nada).

NÃO enviar "midia_path": esse campo não existe mais. A URL de cada foto vem na lista "fotos".

Campos opcionais / preenchidos automaticamente pela API se não enviados:
- data_encontro       -> default: data/hora atual
- data_status_aceito  -> default: data/hora atual
- criado_em           -> default: data/hora atual
- ong                 -> null até uma ONG assumir o chamado
- usuario             -> setado a partir do usuário logado

Exemplo (JavaScript / React Native):
  const form = new FormData();
  form.append('titulo_caixinha', 'Cachorro ferido na praça');
  form.append('tipo_animal', 'Cachorro');
  form.append('quantidade', '1');
  form.append('latitude', '-5.6608');
  form.append('longitude', '-37.7969');
  form.append('cidade', 'Apodi');
  form.append('condicao', 'Machucado');
  form.append('condicao', 'Sangrando');
  form.append('descricao', 'Animal encontrado ferido próximo à praça central');
  form.append('motivo', 'Maus tratos');
  form.append('status', 'aberto');

  // fotosUris = lista de URIs escolhidas pelo usuário (de 1 a 4)
  fotosUris.forEach((uri, i) => {
    form.append('fotos', { uri, name: `foto${i + 1}.jpg`, type: 'image/jpeg' });
  });

  fetch(`${API}/denuncias/`, {
    method: 'POST',
    headers: { Authorization: `Bearer ${token}` },  // sem Content-Type!
    body: form,
  });

Exemplo (navegador / React web, com <input type="file" multiple>):
  const form = new FormData();
  // ... demais campos como acima ...
  for (const arquivo of input.files) {
    form.append('fotos', arquivo);
  }
  await fetch(`${API}/denuncias/`, {
    method: 'POST',
    headers: { Authorization: `Bearer ${token}` },  // sem Content-Type!

Testando no Postman / Insomnia: Body > form-data; crie uma linha com a chave "fotos" do tipo
File pra CADA imagem (a chave se repete). Não preencha o header Content-Type.

Sucesso: 201 Created. A API devolve o objeto criado, no mesmo formato do GET, com "id" novo
e "fotos" já com as URLs:
{
  "id": 7,
  "titulo_caixinha": "Cachorro ferido na praça",
  ...
  "ong": null,
  "usuario": 3,
  "fotos": [
    { "id": 21, "url": "https://xxxx.supabase.co/storage/v1/object/public/pet-photos/denuncias/3/a1b2c3.webp", "ordem": 1 },
    { "id": 22, "url": "https://xxxx.supabase.co/storage/v1/object/public/pet-photos/denuncias/3/d4e5f6.webp", "ordem": 2 }
  ]
}

Erros comuns (400 Bad Request, corpo em JSON). O valor de "fotos" pode vir como lista, como
texto ou como objeto: o jeito mais simples é exibir a mensagem que vier.
- {"fotos": ["Envie pelo menos uma foto do animal."]}
      -> nenhuma foto enviada (ou o campo não se chama "fotos")
- {"fotos": ["Certifique-se de que este campo não tenha mais que 4 elementos."]}
      -> mais de 4 fotos
- {"fotos": {"1": ["Faça upload de uma imagem válida. ..."]}}
      -> o arquivo na posição 1 da lista (contando a partir de 0) não é imagem (ou é HEIC)
- {"fotos": "Cada foto deve ter no máximo 10 MB."}
      -> alguma foto passou de 10 MB
- {"fotos": "Falha ao salvar uma das fotos no storage."} /
  {"fotos": "Não foi possível enviar as fotos agora. Tente de novo."}
      -> problema no servidor de imagens; pode tentar de novo
- {"condicao": [...]}
      -> valor fora da lista permitida

---------- Detalhar (GET /denuncias/{id}/) ----------
Retorna os dados de uma denúncia específica, no mesmo formato do item da listagem.

Como buscar as fotos de novo:
- As fotos vêm sempre junto com os dados, no campo "fotos" de qualquer GET (lista ou detalhe).
  Não existe rota separada para as imagens.
- Cada item tem {"id", "url", "ordem"}. A "url" é pública: para exibir, basta usá-la direto
  na imagem, SEM header Authorization.
- A lista já vem ordenada. Capa do card: fotos[0].url. Galeria: percorrer a lista inteira.

Exemplo (React Native):
  <Image source={{ uri: denuncia.fotos[0].url }} style={{ width: 200, height: 200 }} />

  {denuncia.fotos.map((f) => (
    <Image key={f.id} source={{ uri: f.url }} style={{ width: 200, height: 200 }} />
  ))}

---------- Atualizar completo (PUT /denuncias/{id}/) ----------
Mesmos campos obrigatórios do POST (menos as fotos, que aqui são opcionais).
- Sem foto nova -> pode enviar application/json; as fotos atuais são mantidas.
- Com foto nova -> multipart/form-data, campo "fotos" repetido (mesmas regras do POST).
  As fotos enviadas são ADICIONADAS às que a denúncia já tem (não substituem).
  O total por denúncia nunca passa de 4: se já tem 3 e você manda 2, a API devolve 400.
a API vai devolver o objeto atualizado, com a lista "fotos" completa.
------------------------------------------------------------------

---------- Atualizar parcial (PATCH /denuncias/{id}/) ----------
Front end envia só o que mudou.

Sem foto nova -> application/json, por exemplo:
{
  "status": "atendimento",
  "ong": 2
}

Adicionando fotos -> multipart/form-data, com o campo "fotos" repetido (mesmas regras do POST)
e, se quiser, os outros campos que mudaram. As fotos novas entram DEPOIS das existentes
(a "ordem" continua de onde parou) e a foto de capa (ordem 1) não muda.

ATENÇÃO: por enquanto NÃO existe rota para remover ou trocar uma foto individual pelo app.
Só dá pra adicionar (até completar 4). A remoção de fotos é feita pelo admin do Django.

a API vai devolver o objeto com os dados atualizados:
{
  "id": 1,
  "titulo_caixinha": "Cachorro ferido na praça",
  ...
  "status": "atendimento",
  "ong": 2,
  "fotos": [ { "id": 10, "url": "...", "ordem": 1 }, ... ]
}
------------------------------------------------------------------

---------- Remover (DELETE /denuncias/{id}/) ----------
Remove a denúncia e as linhas de foto dela. Retorna 204 No Content em caso de sucesso.
(Os arquivos das fotos continuam guardados no storage; só deixam de aparecer na API.)
----------------------------------------------------------

---------- Observações sobre os campos ----------
- condicao: campo de múltipla escolha (MultiSelectField). Enviar como lista de strings,
  usando exatamente os valores das opções abaixo:
  "Bem / saudável", "Sujo", "Muito magro", "Fraco / sem forças", "Dificuldade para andar",
  "Dificuldade para respirar", "Parece doente", "Machucado", "Sangrando",
  "Osso ou ferida aberta", "Inchaço ou caroços", "Parasitas", "Sarna aparente",
  "Queda de pelo", "Assustado", "Agressivo", "Muito quieto / parado", "Desorientado",
  "Perto de trânsito intenso"

- fotos: o MESMO nome é usado na entrada e na saída, mas com formatos diferentes:
    ENTRADA (POST/PUT/PATCH): arquivos de imagem no multipart, campo "fotos" repetido (1 a 4).
    SAÍDA (GET/POST/PUT/PATCH): lista de objetos {"id", "url", "ordem"}.
  "ordem" 1 é a foto de capa. A "url" é pública (termina em .webp) e abre direto num <Image>.
  O campo "midia_path" foi removido: use fotos[].url.
  Denúncias do seed de testes (dados falsos) têm caminhos como "seed/denuncia_1.jpg", que não
  abrem imagem de verdade; as criadas pela API têm URL completa do Supabase.

- status: aceita apenas "aberto", "atendimento" ou "finalizado"

- ong: id da ONG responsável pelo chamado (pode ser null enquanto nenhuma ONG assumiu)

- usuario: id do usuário que criou a denúncia (pode ficar null se o usuário for deletado,
  pois o campo usa on_delete=SET_NULL)
